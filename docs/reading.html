02 · Capture and Preparation

Choosing how LocalRIM reads: five text sources compared on 1,400 archival pages

LocalRIM initially used Tesseract to extract text from scanned documents. Before proceeding with classification, I compared five sources of text from the client's archival scans using the same evaluation protocol: Tesseract at two resolutions, PaddleOCR, GLM-OCR, and the existing text layer in the archive's PDFs. The comparison examined transcription accuracy, performance across different scan conditions, and the information needed for subsequent processing.

Stage 2 of 6: Capture

PaddleOCR reads every page; GLM-OCR re-reads the pages in the three difficult scan groups

I compared the five text sources using reference transcriptions, a blind review of selected pages, and an analysis of all 1,400 archival pages. The primary OCR engine was chosen using criteria established before the results were examined.

Built with Tesseract 5.4, PaddleOCR 3.7 and GLM-OCR (through Ollama), scored with jiwer. Full list in the Toolkit

Decisions behind this

What kinds of pages does the archive contain?

Before running OCR, I measured seven image characteristics on each page: brightness, contrast, background, dark share, ink share, speckle, and sharpness. K-means clustering grouped pages with similar visual characteristics, and I inspected examples from each cluster to identify the resulting scan-quality groups.

Scan group
Pages grouped by visual characteristics rather than document content. The groups describe scan quality, not subject matter.

Decisions behind this

I initially selected four clusters before running OCR and examined their composition through visual inspection. A subsequent analysis compared solutions with two to eight clusters using inertia and silhouette scores.

Did the scan-quality groups match visual inspection?

I visually reviewed 22 cluster assignments, including at least four pages from each scan-quality group.

How accurately did the OCR engines reproduce reference text?

The FUNSD dataset provides reference transcriptions for scanned forms. I used forms containing words to compare OCR output with the original text and measure transcription accuracy.

Word recall
The proportion of reference words recovered, regardless of whether each word was transcribed correctly.
Word error rate (WER)
Measures substitutions, deletions, and insertions relative to the reference transcription. Lower values indicate fewer errors.

How did OCR performance vary across scan-quality groups?

I conducted a blind review of 22 pages, with at least four selected from each scan-quality group. The five text outputs for each page were presented without identifying their sources and were rated and ranked against one another. A rank score of 1.00 indicates that a source ranked first on every reviewed page in that group.

Decisions behind this

Did the differences persist across all 1,400 pages?

To examine the full sample, I calculated the proportion of word-like tokens in each text output, defined as tokens containing at least two letters and a vowel. This measure provides an indication of text readability, but does not establish transcription accuracy.

How the OCR engine was selected

I established the selection criteria before evaluating the results, prioritizing transcription accuracy, followed by blind-review ratings, word positions, and confidence scores. Processing speed served as the final tie-breaker (D-52). The evaluation supported PaddleOCR as the primary engine, while GLM-OCR's performance on difficult scans led me to test a hybrid approach for classification (D-53).

Decisions behind this

Output can look correct and still be wrong

OCR output can read smoothly and still differ from the page. In a records system, that can be worse than a visible gap because the error may go unnoticed.

Fluent output
Plausible text that does not accurately reproduce the source document.

Stage 3 of 6: Preparation

Preserving archive identifiers without using them for classification

Bates numbers and litigation stamps were preserved in the OCR output but excluded from the text used for classification. These identifiers could reveal information about a document's origin without reflecting its departmental purpose. Page orientation was also checked before the extracted text was prepared for the classifier.

Decisions behind this

How accurately did the orientation model identify rotated pages?

PaddleOCR includes an orientation model that identifies pages it considers rotated. I evaluated its recommendations before deciding whether the system should apply them automatically.

Decisions behind this

Which text sources recovered the Bates numbers?

Each page contains a Bates number added during litigation. These identifiers are useful for locating and referencing records, so the pipeline preserves them in the extracted text. They are excluded from classifier input to prevent departmental predictions from relying on archive-specific identifiers rather than document content (D-46).

Could Bates numbers predict departments without document content?

To test whether Bates numbers contained information about department membership, I trained a separate model using only the first four digits of each identifier. I then compared the classifier's performance with and without Bates numbers in its text input.

Probe
A separate model trained on the first four digits of each Bates number to test whether the identifier predicts department membership.
